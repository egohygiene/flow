## Executive assessment

flow has a substantial tested library foundation: explicit provider resolution and authority, direct process supervision, host artifact observations, durable run state, fresh dependency assessment and deterministic lifecycle fixtures. A real, digest-pinned, read-only optiflow v0.1.1 adapter is merged. The remaining path to a useful installed suite is already represented by existing released-provider, supported CLI, workflow, local-file UX, packaging and release issues. A second orchestration engine or mandatory AI platform is unnecessary.

Two focused gaps lack an exact current owner: reopened native receipts can accept evidence that violates their declared contract, and current entry documentation can resume already-completed checkpoints. The optional native-test availability reporting gap belongs to existing #34. Preserve the entire backlog; no closure, retitle, label change or scope deletion follows from this report.

The actual downloaded optiflow v0.1.1 Linux binary passed the three native adapter tests, and an emitted receipt independently passed its JSON Schema and runtime reopen checks. However, the unchanged all-target conformance wrapper exceeded its 600-second budget after all 49 lifecycle recipes and 51 of 81 acceptance receipts. The complete Rust suite is **not qualified**. No timeout, assertion, gate or fixture was weakened, and no broad rerun was attempted.

### AUDIT-001 — reopened optiflow receipts bypass declared evidence shape

**Observed:** [`ReadOnlyReceipt::load`](https://github.com/egohygiene/flow/blob/af68afa5732a04c237df5fbeee6bc5e901a5c6fd/src/optiflow.rs) accepts schema-invalid data. An outside-source synthetic driver linked to the frozen library on Rust 1.85.0 loaded a `complete` receipt containing scan/report/plan command names, empty artifact lists and null `plan_sha256`. The result reported `needs_recovery=false`. Independent Draft 2020-12 validation rejected the same receipt because each command requires artifact evidence. The optional comparison can match absence on both sides, while empty artifact lists bypass file re-observation.

Four independent mutations also loaded despite schema rejection: an incorrect environment constant, an extra capability, an omitted required nullable key and an unknown nested native-path property. A schema-valid scanning receipt provided a control. A separately emitted receipt from the exact downloaded v0.1.1 provider passed both schema validation and runtime reopen, so the proposed repair has a real positive control.

**Impact:** medium correctness/compatibility risk; high confidence, confirmed, medium effort. A consumer can receive completed/non-recovery status without the proof required by the receipt's own public contract. Receipts remain editable local audit evidence, not signatures or authority grants. This evidence does not demonstrate mutation/approval bypass, authenticated-provenance forgery or a vulnerability exploit.

**Recommended:** enforce one complete bounded validation contract on emitted/reopened receipts; require a present valid plan digest and actual corresponding artifact evidence for completed/partial state. Add provider-independent negative and positive parity fixtures to ordinary CI. The native receipt schema is outside the 25-contract manifest, so its coverage needs an explicit owner. No particular validation library or new runtime dependency is prescribed.

**Acceptance evidence:** valid native/intermediate/refused receipts retain existing semantics; the five invalid variants refuse; missing proof cannot satisfy an optional equality; changed artifact and unsupported authority refusals remain intact. No open implementation prerequisite is needed. The repair must not broaden mutation or recovery authority.
