# DESIGN_SYSTEM.md Validation Checklist

## Specification

- [ ] `architecture-design-system` is identified.
- [ ] The governing version is known.
- [ ] Required upstream artifacts have been read.

## Primary Question

- [ ] The document answers:
      How should the intended experience be expressed consistently across products, platforms, and implementations?

## Human-Centered Validation

- [ ] Accessibility is treated as foundational.
- [ ] Agency and meaningful control are preserved.
- [ ] Cognitive and sensory load are considered.
- [ ] Trust, feedback, error, and recovery are addressed.
- [ ] Unsupported user assumptions are absent or labeled.

## Boundaries

- [ ] Responsibilities are explicit.
- [ ] Non-responsibilities are respected.
- [ ] Implementation details are excluded.
- [ ] Product-specific exceptions do not silently become universal rules.
- [ ] Shared coherence does not erase distinct product identity.

## Evidence

- [ ] Evidence, inference, and assumptions are distinguishable.
- [ ] Accessibility guidance is traceable.
- [ ] Contradictions and coverage gaps remain visible.

## Completion

- [ ] Acceptance criteria from `architecture-design-system` pass.
- [ ] Downstream impacts are recorded.
- [ ] Metadata and Markdown pass repository checks.
