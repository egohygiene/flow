# ROADMAP.md Validation Checklist

## Specification

- [ ] `architecture-roadmap` is identified as the governing specification.
- [ ] The applicable specification version is known.
- [ ] Required upstream vision, foundations, system, architecture, and methodology documents have been read.

## Primary Question

- [ ] The document clearly answers:
      How should this project evolve over time?

## Boundaries

- [ ] Major initiatives or capability trajectories are explicit.
- [ ] Horizons or phases such as now, next, later, and maybe are understandable.
- [ ] The roadmap is not a backlog, sprint plan, or release checklist.
- [ ] Tactical implementation detail and unnecessary dates are excluded.

## Evidence

- [ ] Strategic priorities are grounded in upstream intent and current architectural reality.
- [ ] Assumptions are labeled.
- [ ] Missing evidence is acknowledged.
- [ ] Contradictions or unresolved prioritization remain visible.

## Flexibility

- [ ] Future options remain distinguishable from commitments.
- [ ] The roadmap preserves strategic adaptability.
- [ ] Future ideas are not silently converted into obligations.

## Completion

- [ ] Acceptance criteria from `architecture-roadmap` pass.
- [ ] Downstream review implications are recorded.
- [ ] Markdown, links, and metadata pass repository checks.
