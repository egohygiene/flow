# META.md validation checklist

## Specification

- [ ] `architecture-meta` is identified as the governing specification.
- [ ] The applicable specification version is known.
- [ ] Required upstream documents have been read.

## Primary question

- [ ] The document clearly answers:

      How is this architecture-document system organized, navigated, validated, and evolved?

## Boundaries

- [ ] Responsibilities are explicit.
- [ ] Non-responsibilities are respected.
- [ ] The document does not duplicate another architecture concern.
- [ ] Provider or implementation details are excluded unless required.

## Evidence

- [ ] Observations and inference are distinguishable.
- [ ] Assumptions are labeled.
- [ ] Missing evidence is acknowledged.
- [ ] Contradictions remain visible.
- [ ] No authority or provenance is fabricated.

## Durability

- [ ] The document remains useful across technology changes.
- [ ] Temporary capabilities do not define enduring governance.
- [ ] Language is clear to humans and agents.

## Completion

- [ ] Acceptance criteria from `architecture-meta` pass.
- [ ] Downstream review implications are recorded.
- [ ] Markdown and metadata pass repository checks.
