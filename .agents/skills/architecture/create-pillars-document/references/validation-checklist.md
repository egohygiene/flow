# PILLARS.md Validation Checklist

## Specification

- [ ] `architecture-pillars` is identified as the governing specification.
- [ ] The applicable specification version is known.
- [ ] Required upstream documents have been read.

## Primary Question

- [ ] The document clearly answers:
      What enduring capabilities must remain strong for this work to succeed?

## Boundaries

- [ ] Responsibilities are present.
- [ ] Non-responsibilities are respected.
- [ ] Implementation detail is excluded unless explicitly relevant.
- [ ] The document does not duplicate another identity concern.

## Evidence

- [ ] Observations and inference are distinguishable.
- [ ] Assumptions are labeled.
- [ ] Missing evidence is acknowledged.
- [ ] Contradictions are visible.

## Durability

- [ ] The document remains meaningful across technology changes.
- [ ] Temporary initiatives do not define the identity concern.
- [ ] Language is clear to humans and agents.

## Completion

- [ ] Acceptance criteria from `architecture-pillars` pass.
- [ ] Downstream review implications are recorded.
- [ ] Markdown and metadata pass repository checks.
