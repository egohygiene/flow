# Copy-Ready GitHub Issue Checklist

Use this checklist after drafting the issue.

- [ ] Title names the problem or outcome precisely.
- [ ] Problem, goal, and current-state evidence are distinct.
- [ ] Scope and non-goals prevent accidental expansion.
- [ ] Acceptance criteria are observable and implementation-scoped.
- [ ] Validation commands are included only when evidence supports them.
- [ ] Dependencies, migration, security, privacy, accessibility, and documentation notes appear only when relevant.
- [ ] Copying the issue into GitHub preserves the intended formatting.
