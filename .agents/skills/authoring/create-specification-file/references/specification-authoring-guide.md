# Specification Authoring Guide

## Before Writing

Identify the problem, owner, evidence, accepted decisions, unresolved
questions, and downstream implementation consumers.

## Strong Requirement

    FR-001: The system MUST preserve immutable historical audit reports.

## Weak Requirement

    The system should be robust and good.

## Boundary Test

Say enough to constrain implementation and validation without becoming
the implementation itself.

## Issue Generation Test

A strong specification can produce small issues with source requirement
IDs, scope, outcome, validation, and acceptance criteria.
