# Four-tool installed music candidate

The music observer uses the existing `suite-install`, native Aniflow adapter and
explicit candidate acknowledgements. It adds no installer, media engine, release
or permission to publish. Its first measured [checkpoint](../work/75/INSTALLED-MUSIC-CANDIDATE-20261115.md)
retains the actual source, installed-byte and refusal observations.

`tools/installed_music_candidate_subjects.py` defines an explicit closed
`flow.installed-candidate-selection/v2` document. The historical v1 observer stays
closed to its original two-provider/three-tool package projection. V2 selects
Aniflow, Renderflow and the actual released Optiflow v0.1.1, plus one derived Flow
self row, through a separately pinned candidate supplement. Exact provider files,
compiled descriptors, source/build observations, original Optiflow bundle,
installation intent/receipt and current copied bytes must join.

The original verified Flow package remains the Flow executable/build identity.
Its sealed two-provider cohort is never rewritten or claimed to cover new
providers. A separately pinned Git product-input comparison explains why an
older exact build can be reused when only documentation/observer files changed.
The new supplement is explicitly unsealed and unpublished; no package, source
authentication or native qualification is inferred from installation.

The private installation input document supplies the v2 source/package/build
selections plus `provider_rows` and `provider_files`. The fixture assembler
creates a fresh request and invokes the existing installer; it refuses a missing
candidate acknowledgement before destination creation. Keep these files private:
they contain local source and installation paths. Public reports project named
identities and hashes only.

```text
python3 tools/prepare_music_candidate_installation.py --inputs /private/music-install-inputs.json --output /private/fresh-install-proof
python3 tools/check_installed_music_video.py --selection /private/fresh-install-proof/selection-v2.json --source /private/synthetic-ordinary.mp4 --recipe /private/source-recipe.json --tool-directory /private/pinned-video-tools/bin --output /private/fresh-native-proof
```

The direct proof executes installed Flow and installed Aniflow. It observes
accepted clean-master/delivery artifacts, current source/provider/intent joins,
status, completed resume, missing/stale subjects and exact named refusals. A
separate bounded cancellation case first identifies a direct child of the owned
Flow process with the installed Aniflow executable inode, then sends SIGINT to
Flow. It verifies structured 130 and retained recovery. It establishes neither
descendant shutdown nor process-tree containment. Older attempted observations
and their limits remain retained instead of being overwritten.

The music-state inventory reuses the existing held-file observer with explicit
64 MiB/member, 512 MiB aggregate and 4,096-entry limits; historical defaults remain
unchanged. These observation limits accommodate Aniflow's retained pinned provider
and have a separate meaning from requested final-output budgets.

Native completion and execution acknowledgement never approve lyrics, timing,
appearance, sound, rights or a final package. The existing reusable project,
publishing pilot and private delivery owners retain those separate handoff and
review responsibilities.
