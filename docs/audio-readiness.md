# Publishing audio readiness

The audio-readiness summary pairs every assigned delivery media file and
destination with a chosen audio policy, the owner's level check and the package's
current review declarations. It does not master audio or choose one loudness
number for every song. Aniflow owns loudness/peak math and exact-final-file QC.

Use a current private [delivery package](delivery-package.md) and its separately
retained manifest digest. A `flow.audio-readiness-request/v1` contains:

| Field | Selection |
| --- | --- |
| `package_manifest` | Exact `manifest.json` FilePin: native path, SHA-256 and bytes |
| `timeout_ms` | Explicit whole-check deadline, 1..86400000 |
| `selections` | One unique `payload_id` / `destination` choice for every assigned media pair, at most 128 |

Video delivery, audio derivatives, original audio and clean masters require
coverage. Artwork, lyrics and supporting documents do not become audio. Each
selection's `choice` is either:

- `check`, containing a pinned existing native `plan` and `authority`. The plan
  selects Aniflow's `audio-policy-check-v1`, one exact final media file and an
  explicit `aniflow.audio-policy-check-request/v1` configuration. That file's
  digest/length must equal the package payload; a byte-identical owned copy can
  have a different path. The authority is `source_candidate` or `released`, with
  its exact existing approval FilePin. No approval is generated by this workflow.
- `keep_archive_master`, with an explicit bounded `reason`. This is allowed only
  for the archival destination's clean master/original audio. It preserves that
  master without claiming a target check; platform copies/derivatives cannot skip.

The native SDK's existing prepare/approve interfaces create the chosen exact
plan and operator declaration. Aniflow's compiled descriptor must actually
advertise this route; older descriptors or unavailable cohort rows refuse.
This source checkpoint does not supply a real qualified provider/release cohort.

```bash
flow audio-readiness-preview --request selected-audio-checks.json --format json
flow audio-readiness-run --request selected-audio-checks.json --format json
flow audio-readiness-run --request selected-audio-checks.json --output /private/audio-readiness.json --format json
```

Equivalent preview and source-candidate tasks are available:

```bash
task audio:readiness:preview REQUEST=/private/selected-audio-checks.json
task audio:readiness:run REQUEST=/private/selected-audio-checks.json
```

Released checks use the full CLI with the existing `--evidence-request`,
`--verification-directory`, `--verification-policy`, `--policy-sha256`,
`--verifier-executable` and `--verifier-sha256` selections. Any verification
networking keeps the existing explicit acknowledgement boundary. SDK callers
instead supply the existing opaque `VerifiedEvidence`; a serialized verified
flag cannot replace it. Task convenience for run covers source-candidate mode.

Preview reads package membership/pins, exact policy plans and authority files.
It invokes no program, creates no workspace and does not claim levels were
checked. Explicit run requires fresh disjoint native check roots and existing
exact approvals. The current Aniflow CLI rechecks final-file QC, with no codec,
meter/model processing or upload. Flow reuses its existing bounded runner and
records the owner response as supporting evidence. It checks schema/framing,
units, complete channel scope, availability, source/policy identity and digest;
it does not duplicate the owner's loudness comparison algorithm.

Rows expose the chosen goals, integrated-loudness and true-peak observations,
matches/outside/missing states, exact payload bytes and the retained native
record. Summary also carries pending/changed review scopes, missing metadata or
destination files and qualification state. Goal matching does not supply a
musical review. `upload_authority` and `current_platform_compliance_verified`
remain false. Current Aniflow meter observations remain unqualified; a matching
target can therefore still produce a partial overall outcome.

Every gain/AAC encode, caption mux or metadata edit needs QC and a policy check
of the new exact file. A saved successful result remains a historical snapshot.
Native local status reobserves selected bytes and record identity but does not
refresh the QC owner. Request a fresh explicitly approved check for current
readiness. If a batch fails, ordinary native attempts/receipts remain; no new
replay/state engine adopts or overwrites them. Reports and verifier output must
stay outside packages, originals, provider/configuration, native workspaces and
the selected Aniflow QC/native evidence directories.

All focused protocol/source/scope/archive/parser cases and contracts are
authored, uncompiled/unrun. No tests/compiler/build/package/dependencies/lint/
format/schema/docs/drift/product validators, CLI/SDK/native/media/provider/model/
browser/container/CI, acquisition, actual source replacement/disposal, signing/
timestamps or publication ran. Provider release, clean-install/interoperability,
native/reference-meter and musical qualification remain unfinished under the
existing owners. Flow #88 stays last and unchanged; known alignment cancellation/
start-marker failure unresolved, cause unproven. ADR-0019 remains proposed.
