# Actual four-CLI terminal presentation — November 14, 2026

Relates to [#22](https://github.com/egohygiene/flow/issues/22).

All **108 cases / 136 actual CLI invocations** pass for four explicitly pinned,
independently built Linux executables. The [portable observation](PTY-20261114.json)
records native output hashes, binary/static-asset identities and measured source
bindings. These are local candidates, with different documented build revisions;
this does not claim a single released suite or a newly compiled combined tip.

`tools/check_root_help_pty.py` drives real POSIX pseudo-terminals and separate
stderr capture. Both literal root-help spellings show exactly one checked-in
wordmark on a wide supported terminal. Removing that exact mark and ordinary
SGR styling reproduces the redirected semantic help bytes. The other 18 root
cases per tool cover redirected, 40-column (environment and real PTY width),
dumb/unknown/missing terminals, missing/invalid widths, empty `NO_COLOR` and
`CLICOLOR=0`: each is undecorated and has no ANSI sequences. Product names and
command text remain ordinary text. Each selected input is rehashed afterward;
no presentation command writes files in the fresh working directory.

Seven additional cases per tool compare semantic `help`, version, parse errors,
subcommand help, unsupported completion/man help requests and actual structured
release descriptions. Native exits, stderr and semantic text agree with each
selected binary's redirected baseline; structured output remains valid native
JSON without ANSI. Only ordinary SGR is allowed on supported decorated help and
non-root human presentation; cursor controls and other escapes always fail.
These checks do not establish historical-binary compatibility or perform actual
completion/man generation, since those generators are absent.

The first observer incorrectly rejected supported wide-terminal SGR styling;
that observer failure remains private history and is not a product diagnosis.
After allowing only ordinary SGR on eligible paths, real narrow/unknown and empty
`NO_COLOR` root fallbacks still exposed ANSI in Aniflow, Optiflow and Renderflow.
Their separate owning-repository patches now use Clap's color-unaware `Display`
on the literal root plain path. Selected wide help and ordinary commands retain
their owners. Flow already produced plain fallback text and needs no product fix.

Eight observer regressions reject missing/repeated art, changed semantic text,
extra stderr, changed exits, ANSI on plain paths and cursor-control substitution.
Independent source review confirmed the literal-root guards and unchanged wide
paths in all three repairs. Actual broken-pipe handling was not exercised.
Human wordmark approval, design/licensing review, screen-reader qualification,
other native targets, general terminal emulators and final #88 acceptance remain
separate. Static assets are unchanged; no cross-holon package, logger, exporter,
domain execution, model, hosted CI, release, signing or publication is added.
