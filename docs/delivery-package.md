# Build a private local delivery package

The delivery SDK collects selected accepted outputs, operator metadata, retained
evidence and a review checklist. It copies exact bytes into a fresh private
directory. It does not transform media, trim/reframe a video, normalize a mix,
verify current platform requirements, sign, timestamp or upload anything.

First enumerate the exact native artifact IDs from a completed project/pilot:

```text
flow delivery-catalog --project-record /private/song-work/prepared-project.json --project-record-sha256 EXACT_RECORD_SHA --handoff /private/song-work/pilot/handoff.json --handoff-sha256 EXACT_HANDOFF_SHA --format json
```

For a released pilot, select its exact `released-handoff.json` and digest. The
catalog reobserves the current native domain acceptance and final artifact bytes.
It preserves released handoff history without asserting fresh publisher/native
admission. Candidate and released execution authority remain separate; packaging
only needs accepted artifacts and explicit local copy intent.

Copy the inert [request template](../examples/publishing/delivery-request.json.in),
fill its pins, and choose catalog artifact IDs, roles, output filenames and
destinations. Native video roles come from Aniflow's actual accepted artifact
variants: a clean master is never inferred from a filename. The package must
retain a real clean archival master. Native text/audio derivatives retain their
owner identities. You may explicitly select the unchanged original song audio,
manual SRT, and external artwork/supporting documents; external files remain
unqualified selections pending domain checks.

```text
flow delivery-preview --request /private/delivery-request.json --format json
flow delivery-prepare --request /private/delivery-request.json --format json
flow delivery-status --directory /private/song-delivery --manifest-sha256 EXACT_MANIFEST_SHA --format json
```

Preview is read-only. It resolves the exact payload collection, metadata digest
and package subject, supplied review states, missing creators and destinations
without selected files. Prepare checks the complete byte budget before creating
the directory, uses the existing bounded streaming copy boundary, reobserves the
source/native/review context and commits `manifest.json` last. Cancellation or
changed bytes preserve an incomplete package rather than overwriting or replaying
work. Originals and native workspaces remain unchanged.

The private package contains:

- `archive/`: the selected accepted clean master.
- `deliver/`: explicitly selected destination candidates and supporting files.
- `metadata.json` and `delivery-index.json`: operator metadata and relative file
  identities, without automatically inserted original host paths.
- `evidence/`: exact selected project/handoff/native receipt and domain-acceptance
  snapshots, the manual SRT, supplied reviews and optional attachments.
- `intent.json` and `manifest.json`: private request, exact owned membership,
  SHA-256/size ledger, proof scope and pending work.

Keep the whole directory private: retained evidence/intent can contain original
host paths. Actual later uploads select only their intended files after separate
review and domain preflight. An evidence attachment is retained data; packaging
does not turn it into a verified platform result or reproduce the full original
native workspace/signature chain.

Words, timing, visual, audio and final-package scopes remain distinct. Optional
`flow.delivery-review/v1` records must match the preview's exact package-subject
digest and contain a real supplied operator, time, scope, decision and notes.
The [review template](../examples/publishing/delivery-review.json.in) is deliberately
inert; no review is generated by preview or prepare. Changed payloads, role/name/
destination choices, project/handoff or metadata invalidate those package reviews.
Duplicate/stale scopes refuse; rejection or requested changes stay visible.
The result labels supplied records as unauthenticated operator declarations and
always retains `publishing_authority: false` and
`current_platform_compliance_verified: false`. Domain-owned checks and final
publishing authority remain separate even when every declaration is supplied.

Status verifies the exact external manifest pin, copied bytes, metadata/index,
review summary and full owned membership, refusing changed, unknown, linked or
special files. It can read back a moved intact package using relative members
without the original host paths. This is portable byte/evidence retention, not a
new native domain run or fresh release qualification. No cleanup or deletion
operation is introduced.

Source checkpoint only: no private music/media, test, build/compiler/validator,
CLI/SDK/catalog/copy/native/provider/model/installer, CI, acquisition, signing or
publication was executed. Actual human/domain review remains pending; existing
roadmap qualification stays open and Flow #88 remains last.
